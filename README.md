# Fair vs Last Price Scanner

Парсер на Python / FastAPI, который периодически сравнивает **fair price** (mark price) и **last price** на USDT-маржинальных
бессрочных фьючерсах на семи биржах:

- **Binance** — `/fapi/v1/ticker/24hr` + `/fapi/v1/premiumIndex`
- **MEXC** — `/api/v1/contract/ticker`
- **Gate.io** — `/api/v4/futures/usdt/tickers`
- **Bybit** — `/v5/market/tickers?category=linear`
- **OKX** — `/api/v5/market/tickers?instType=SWAP` + `/api/v5/public/mark-price`
- **Bitget** — `/api/v2/mix/market/tickers?productType=USDT-FUTURES`
- **KuCoin** — `/api/v1/contracts/active`

При расхождении (`|last - fair| / fair * 100% ≥ min_spread_pct`) тикер попадает в таблицу аномалий в веб-интерфейсе.

## Что умеет

- Фоновый асинхронный сканер (`asyncio.gather` по всем биржам, выполняется каждые `scan_interval_sec` секунд, минимум — **1 секунда**).
- Веб-интерфейс с двумя вкладками:
  - **Сканер** — параметры сканирования и таблица текущих аномалий:
    - включение/отключение каждой биржи,
    - минимальный объём торгов за 24 ч (USDT),
    - минимальный спред (порог открытия ситуации), %,
    - порог схождения (закрытия ситуации), %,
    - интервал сканирования (≥ 1 сек),
    - **HTTP / HTTPS / SOCKS5 прокси** для всех запросов к биржам,
    - **звуковое оповещение** при появлении новой аномалии выше заданного порога.
  - **История** — журнал событий «спред появился → сошёлся»:
    - время открытия и закрытия (UTC), длительность,
    - спред в момент открытия, пиковый |спред| за время жизни события, спред в момент закрытия,
    - фильтры по бирже, символу, статусу (открыт/закрыт), диапазону времени, минимальному пиковому |спреду|,
    - пагинация (50 / 100 / 200 / 500 строк на страницу).
- Сохранение настроек в `data/config.json` и истории событий в `data/history.db` (SQLite) между перезапусками.
- Сводка по биржам (зелёный/жёлтый/красный индикатор, количество тикеров, последняя ошибка).
- Таблица аномалий, отсортированная по абсолютной величине спреда; новые строки коротко подсвечиваются.

## История ситуаций

Каждая аномалия превращается в *ситуацию* — событие со временем начала и схождения:

1. **Открытие**: фиксируется в момент, когда впервые выполняется `|spread| ≥ min_spread_pct` И `volume_24h ≥ min_volume_usdt`. Записывается `opened_at`, `open_spread_pct`, цены и объём.
2. **Пик**: пока ситуация открыта, поле `max_spread_pct` (со знаком) и `max_abs_spread_pct` обновляются на каждом тике, если новое значение |спреда| больше предыдущего пика.
3. **Закрытие**: фиксируется в момент, когда впервые выполняется `|spread| ≤ close_threshold_pct` (по умолчанию **0.5 %**). Записывается `closed_at`, `close_spread_pct`, цены на момент схождения.

Гистерезис: чтобы ситуация не флапала на одном и том же тике, `close_threshold_pct` должен быть строго меньше `min_spread_pct`. Если пользователь задаёт значение, нарушающее это, сканер автоматически опускает порог закрытия чуть ниже порога открытия.

История хранится в SQLite-файле `data/history.db`. Состояние открытых ситуаций восстанавливается при перезапуске.

## Запуск

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

или просто:

```bash
python main.py
```

Открыть в браузере: <http://localhost:8000/>

### Запуск из PyCharm

В корне репозитория лежит `main.py` — это точка входа для IDE. После открытия проекта в PyCharm:

1. **PyCharm → Settings → Project: scanner → Python Interpreter** — указать интерпретатор (можно создать `venv` через PyCharm: «Add Interpreter → Virtualenv Environment»).
2. **PyCharm → Run → Edit Configurations…** — там уже будет готовая конфигурация **Scanner** (берётся из `.idea/runConfigurations/Scanner.xml`). Если её нет, можно просто открыть `main.py` и нажать зелёную ▶ рядом с `if __name__ == "__main__":`.
3. Нажать ▶ Run — приложение поднимется на `http://127.0.0.1:8000/`.

Параметры запуска можно переопределить переменными окружения в Run Configuration:

| Переменная | По умолчанию | Что делает |
| ---------- | ------------ | ---------- |
| `HOST`      | `127.0.0.1`  | адрес для bind |
| `PORT`      | `8000`       | порт |
| `RELOAD`    | `0`          | `1` → hot-reload при изменениях файлов (удобно при разработке) |
| `LOG_LEVEL` | `info`       | уровень логов uvicorn |
| `SCANNER_CONFIG` | `data/config.json` | путь к файлу настроек |

### Через Docker

```bash
docker build -t scanner .
docker run -p 8000:8000 -v $(pwd)/data:/app/data scanner
```

## Прокси

В поле «Прокси-URL» можно указать:

- `http://user:pass@proxy.example.com:8080`
- `https://proxy.example.com:8080`
- `socks5://user:pass@proxy.example.com:1080`

Прокси применяется ко всем биржам (Binance и Bybit отказывают по гео-IP — без прокси они вернут ошибку, которая будет
видна на карточке биржи в UI; остальные пять обычно доступны напрямую).

## Звуковое оповещение

В блоке «Звуковое оповещение» можно:

- **Включить звук** — двухтонный сигнал (880 → 1320 Гц), генерируемый через Web Audio API, не требует внешних файлов.
- **Порог срабатывания, %** — самостоятельная величина, не зависит от `min_spread_pct`. Сигнал звучит, когда в свежем
  результате появляется аномалия `(биржа, символ)`, которой не было выше порога на предыдущей итерации.
- **▶ Тест звука** — проиграть сигнал вручную (нужно, чтобы первый клик «разблокировал» аудио по политике браузера).

Подсветка новой строки в таблице длится ~2.5 секунды, чтобы её было видно глазом одновременно со звуком.

## Частота сканирования

Минимально допустимый `scan_interval_sec` — **1 секунда**. Имейте в виду:

- На высокой частоте запросы могут упереться в IP-лимит конкретной биржи (особенно Binance — `weight 50` за полный скан,
  `2400/min` лимит на IP). При 429-х ошибках увеличьте интервал или отключите проблемные биржи.
- Создание HTTP-клиента происходит на каждый скан, поэтому при использовании прокси с большим RTT 1-секундный интервал
  может «не успевать» — UI отобразит это в виде задержанного `last_scan_at`.

## API

| Метод | Путь | Описание |
| ----- | ---- | -------- |
| GET   | `/api/exchanges`      | Список поддерживаемых бирж. |
| GET   | `/api/settings`       | Текущие настройки. |
| POST  | `/api/settings`       | Сохранить настройки (JSON `ScannerSettings`). |
| GET   | `/api/scan`           | Результат последнего сканирования. |
| POST  | `/api/scan/run`       | Запустить сканирование немедленно. |
| GET   | `/api/history`        | История ситуаций c фильтрами и пагинацией. |

`GET /api/history` принимает query-параметры: `exchange`, `symbol` (подстрока, LIKE), `status` (`open`/`closed`), `from_ts`, `to_ts` (UNIX-секунды), `min_abs_spread` (%), `limit` (1–500, по умолчанию 50), `offset`.

Пример обновления настроек:

```bash
curl -X POST http://localhost:8000/api/settings \
  -H 'content-type: application/json' \
  -d '{
    "exchanges": {
      "binance": {"enabled": true},
      "mexc":   {"enabled": true},
      "gate":   {"enabled": true},
      "bybit":  {"enabled": true},
      "okx":    {"enabled": true},
      "bitget": {"enabled": true},
      "kucoin": {"enabled": true}
    },
    "min_volume_usdt": 1000000,
    "min_spread_pct": 0.5,
    "close_threshold_pct": 0.5,
    "scan_interval_sec": 1,
    "proxy_url": "http://user:pass@proxy.example.com:8080",
    "sound_enabled": true,
    "sound_threshold_pct": 1.0
  }'
```

## Замечания

- На каждой бирже `fair price` имеет своё имя поля (`fairPrice`, `mark_price`, `markPrice`, `markPx`), это уже учтено
  в соответствующих клиентах.
- Символы нормализуются к виду `BASE/USDT` (XBT KuCoin → BTC).
- Объём 24 ч приводится к USDT для всех бирж (для OKX SWAP — `volCcy24h * last`, для остальных — родное поле в quote-валюте).
- Если биржа недоступна (например, без прокси), её ошибка отображается на карточке и не ломает остальное сканирование.
